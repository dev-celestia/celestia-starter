# 2026-09-21

## Design system overhaul — `packages/ui` token layer

Audited the whole design system (141 components, 1 CSS file) and shipped a token-layer +
accessibility pass. Verified numerically before changing anything.

### Bugs found and fixed

1. **Dark elevation inversion** — `--background` was `oklch(21.779% 0.00002 271.152)` (#1a1a1a)
   while `--card`/`--popover`/`--sidebar` stayed at `oklch(0.205 0 0)` (#171717). Every card,
   popover, dialog and sidebar rendered *darker* than the page. Restored the ramp to
   `oklch(0.145)` (#0a0a0a) — which also matches the landing palette's `--bg`, so both
   palettes now share one base.
2. **`--font-sans: var(--font-sans)`** in `@theme inline` — a CSS dependency cycle. Confirmed
   by compiling with the Tailwind v4 CLI: `@theme inline` *does* emit the variable, so
   `font-sans` resolved to nothing unless a consumer overrode it. Fixed by introducing
   `--font-sans-family` / `--font-mono-family` as the override hooks.
   **Contract change:** `apps/web/app/layout.tsx` now passes `variable: "--font-sans-family"`
   and `"--font-mono-family"` to next/font. Use these names, never `--font-sans`.
3. **`--destructive-foreground` was documented but never defined**, forcing `text-white` in
   the destructive Button. White on the dark destructive surface (#ff6467) is 2.89:1 at full
   strength and 3.46:1 on hover — both below AA. Added the token per theme (white in light,
   `oklch(0.205 0 0)` in dark) and dropped the `dark:bg-destructive/60` alpha workaround.
4. **Light `--ring` was 2.58:1 on white**, below the 3:1 WCAG 2.4.11 focus-indicator minimum.
   Now `oklch(0.55 0 0)` (4.88:1).
5. **`--sidebar-primary` dark was a saturated blue-violet** (`oklch(0.488 0.243 264.376)`) —
   the only chromatic value in an otherwise achromatic palette. Now matches its light role.
6. **Brand accent was not a token.** `#89aacc` / `#4e85bf` were hardcoded in `landing.css` and
   across 8 landing components. Added `--brand` / `--brand-deep` / `--brand-foreground`
   (+ `bg-brand`, `text-brand`, `border-brand`, `bg-brand-deep` utilities) and replaced every
   literal with a utility.
7. **Three different overlay opacities** for the same scrim: Dialog/Sheet `bg-black/70`,
   Drawer `bg-black/80`, AlertDialog `bg-black/10`. Unified behind `--overlay` → `bg-overlay`.

### Consistency + a11y

- **Focus rings normalised** across 17 files to one canonical treatment:
  `focus-visible:ring-2 focus-visible:ring-ring`. Was 5 widths (1/2/3px) and 2 dilutions
  (`ring/30`, `ring/50`). Diluted rings landed near 1.4:1 on white.
- **Reduced motion** is now handled globally in `globals.css` (`0.01ms`, not `none`, so
  `animationend`/`transitionend` still fire for Base UI popups). Previously only 2 components
  opted in via `motion-reduce:`.
- Added `color-scheme` per theme, `::selection` token, `text-wrap: balance` on h1–h3,
  `text-wrap: pretty` on p.
- Added a `--duration-*` scale (80/150/220/320/500ms), `--radius-xs`, and elevation tokens
  (`--shadow-3d`, `--shadow-3d-primary`) so Button stops repeating inline shadow literals.

### Docs

Fixed drift across `design-system.mdx`, `components/index.mdx`, `packages.mdx`,
`packages/ui/README.md`, `docs/README.md`, `docs/implementation-details.md`:
dark `--destructive` / `--border` / `--ring` values were wrong, the radius table was off by
2–4px per step, and component counts ranged from "60+" to "120+" (actual: **126** modules =
47 primitives + 25 composites + 54 AI).

### Verification method

Compiled the real `globals.css` with `@tailwindcss/cli@4` in an isolated scratch dir
(`~/.workbuddy-ai/binaries/node/workspace/twcheck*`) and asserted: 0 CSS variable cycles,
every new utility emitted, no hex literals left in code. Contrast ratios computed from an
OKLCH→sRGB converter rather than eyeballed.

### Left alone (flagged, not changed)

- `--chart-1..5` are entirely greyscale in both themes, so the Chart component renders
  monochrome. Intentional-looking, but a brand-anchored ramp may be wanted.
- `bg-white` on the Slider thumb — theme-independent by design, documented as the one
  allowed literal.
- ~44 components still have no focus styling of their own (dialog, table, breadcrumb,
  calendar, command…). Low risk since they're containers, but worth a sweep.
- `packages/alpine-ui` is a parallel port with its own `globals.css` copy — it will drift.

## `apps/web` design pass + motion-token repair

Second pass, this time on the app. Two threads: stop `apps/web` bypassing the design
system, and repair a silently-dead token group found along the way.

### The big one: the `--duration-*` scale generated nothing

The duration tokens added in the first pass produced **zero utilities**. Two independent
mistakes, neither of which warns:

1. **Wrong namespace.** Tailwind v4 generates `duration-*` from
   `--transition-duration-*`. There is no `--duration-*` namespace.
2. **Wrong placement.** They were in `:root`, not `@theme`. Only `@theme` declares a
   namespace, so a `:root` custom property never becomes a utility.

The failure was invisible because bare numerics (`duration-200`) work with no theme entry,
so the codebase mostly used raw numbers. Fixed by renaming and moving them into
`@theme inline`; verified by compiling and grepping for `.duration-fast`.

Docs were wrong too — `design-system.mdx` told consumers to write
`duration-[var(--duration-fast)]`, referencing the dead name.

Then migrated 91 raw durations (67 first sweep + 24 off-scale in `packages/ui`) onto the
scale, plus 7 arbitrary easing curves that exactly matched a token
(`ease-[cubic-bezier(0.32,0.72,0,1)]` → `ease-drawer`). Kept `duration-0` and
`duration-[calc(...)]` — functional, not stylistic.

### Status tokens

`--success` / `--warning` / `--info` (+ `-foreground`) added per theme, and 62 palette
literals migrated across 16 files. Quantified why literals can't work: `text-green-500`
2.22:1, `text-amber-500` 2.13:1, `text-sky-500` 2.71:1 on white; `text-amber-900` 2.53:1
and `text-amber-200` 1.24:1 on dark. Also proved **no single OKLCH lightness serves both
themes** — the curves cross near L≈0.575 at ~3.7:1, under AA — hence per-theme values.

### Structure / UI fixes

- **Auth** pages were ~95% duplicated → extracted `components/auth/auth-chrome.tsx`.
  `AuthError` now has `role="alert"` (errors were silent for screen readers).
- **Auth layout** right panel used `from-primary/20`, and `--primary` is achromatic here,
  so it rendered flat grey. Re-anchored on `--brand` and added the logo mark.
- **Auth buttons**: `className="h-8 w-full text-xs"` re-declared the Button's *default*
  size and clobbered its `text-xs/relaxed` line-height → now `size="lg"`.
- **Dashboard sidebar**: fixed `w-56` ate 224px of a 375px viewport → 56px icon rail below
  `md`, names preserved via `aria-label`, plus logo mark and focus ring.
- **Dashboard loading**: bare `Loading...` → skeleton mirroring the real sidebar/main split.
- **Dashboard overview**: extracted `StatRow`; User ID was `text-[0.625rem]` (10px, below
  the smallest step) and long values lacked `min-w-0`/`truncate`.
- **LogoMark** extracted out of the `"use client"` nav-bar to
  `components/shared/logo-mark.tsx`; 4 importers updated.
- `stack-section.tsx`: arbitrary cubic-bezier → `ease-out` (the token *is* that curve).
- `callout.tsx` rewritten onto a 4-tone map; its old per-type classes did nothing.

### Verification

- Compiled the real stylesheet against repo sources; asserted every token utility emits,
  with a control class that must not.
- `tsc --noEmit --noResolve` over 256 ts/tsx files: **0 syntax errors** (rest is
  `--noResolve` noise).
- **Tooling caveat that cost real time**: BSD `grep -E` supports neither `\b` nor `\s`.
  Two separate false conclusions in this session came from zero-counts that were grep
  artifacts, not real absences. Always re-confirm a zero count with ripgrep or Python.

### Left alone (flagged)

- `packages/alpine-ui` + `apps/alpine-ui`: parallel Alpine.js port with its own
  `globals.css` copy and ~30 raw durations — out of scope, will drift.
- `drawer.tsx` `ease-[cubic-bezier(0.45,1.005,0,1.005)]` and `message-scroller.tsx`
  `ease-[cubic-bezier(0.7,0,0.84,0)]` have no token equivalent; left rather than rounded.
- `--chart-1..5` still entirely greyscale (carried over from the first pass).
