# CMS Feature for apps/celestia — Blog Post Management (PRD implementation)

## Context & decisions

- **Target**: `apps/celestia` (self-contained Next.js 16 fullstack app, port 3100, own `lib/db` + Better Auth + route handlers). It diverges from the apps/web+apps/api split, so all CMS code targets celestia's own patterns (Next route handlers, `@/lib/db`, `requireSession`-throws-Response, raw `fetch`, semicolons).
- **Delivery**: installable feature package `features/cms/` installed via `pnpm add-feature cms` (mandatory per AGENTS.md). The feature-manager supports arbitrary target dirs; I'll add the required `feature-manager:*` marker regions to celestia files as one-time prep.
- **Editor**: YOUR `BlockTextEditor` (`@celestia-project/ui/components/block-text-editor`) is used as-is — never modified. It's markdown-in/markdown-out (`content`, `onUpdateContent`) with an `onFilesDrop` hook that the CMS wires to the upload API (replacing its base64 default).
- **Roles**: extend `user.role` to `user | writer | editor | admin` (PRD personas). Server-side RBAC helpers gate every CMS mutation; UI gates nav/pages.
- **Media**: upload API stores under `apps/celestia/public/uploads/`, converts to WebP with `sharp`, returns URLs inserted as markdown images.
- **Public blog**: yes — `/blog` + `/blog/[slug]` public pages with full SEO metadata, robots directives, canonical URLs, and 301 redirects.

## 1. Prep edits in apps/celestia (host wiring, one-time)

1. `lib/db/schema.ts` — add empty `feature-manager:tables:begin/end` marker region (CMS tables get inserted there on install).
2. `components/dashboard/sidebar-nav.tsx` — add `imports` + `nav` marker regions; change props from `isAdmin` to also accept `role` so CMS links can be role-filtered (visible to writer/editor/admin only).
3. `app/(dashboard)/dashboard/layout.tsx` — pass `role={session.user.role}` to `SidebarNav`.
4. `app/api/users/route.ts` (and `[id]` route if applicable) — extend the role zod enum to accept `writer`/`editor` so admins can assign CMS roles.

## 2. Data model (inserted into `apps/celestia/lib/db/schema.ts`)

- `post` — id (`post_…`), title, slug (unique idx), contentBody (markdown text), excerpt, featuredImageUrl, featuredImageAlt, status (`draft|pending_review|scheduled|published|archived`), primaryCategoryId → category (set null), publishedAt (scheduling + publish timestamp), seoTitle, seoDescription, ogTitle, ogDescription, ogImageUrl, canonicalUrl, noindex, nofollow, guestAuthorName, createdBy → user, updatedBy, lockedBy, lockedAt (soft-lock), createdAt, updatedAt.
- `category` — id, name, slug (unique), parentId → self (hierarchy), description.
- `tag` — id, name, slug (unique); `postTag` — composite pk (postId, tagId).
- `postAuthor` — (postId, userId, position) for multi-author bylines.
- `postRevision` — id, postId (cascade), snapshot jsonb, label, createdBy, createdAt.
- `slugRedirect` — oldSlug (unique) → postId; 301 on slug change after publication.
- `mediaAsset` — id, filename, originalName, mimeType, width, height, bytes, variants jsonb, altText, uploadedBy, createdAt.

## 3. Backend — API route handlers (`app/api/cms/…`)

Shared helpers in `lib/cms/`: `rbac.ts` (`requireRole`, permission matrix: writer = create/edit-own drafts + submit; editor = edit all, review, schedule, publish, taxonomy; admin = all + delete + redirects), `status.ts` (enforced status state machine: draft→pending_review→scheduled/published→archived, reject→draft), `slug.ts` (slugify + uniqueness), `autosave/lock` helpers, `publish-sweep.ts` (lazy `publishDuePosts()` — scheduled posts with `publishedAt <= now` flip to published; invoked by public + list queries so no cron needed).

Routes (all with `requireSession` + RBAC, zod validation, `Response.json`):
- `posts/route.ts` GET (filters: status, author, category, tag, q, pagination) / POST create
- `posts/[id]/route.ts` GET / PATCH (auto-save + manual save; creates revision snapshot per PRD on manual save & status change; generates slugRedirect when published slug changes) / DELETE (admin)
- `posts/[id]/submit`, `posts/[id]/review` (approve→schedule/publish, reject→draft with comment), `posts/[id]/lock` (soft-lock heartbeat/release), `posts/[id]/revisions/route.ts` + `revisions/[revisionId]/route.ts` (GET snapshot) + `revisions/[revisionId]/rollback` (POST)
- `categories/route.ts`, `categories/[id]/route.ts` (editor+), `tags/route.ts` (GET autocomplete, POST)
- `upload/route.ts` (multipart → sharp WebP + responsive variants → public/uploads, alt-text required in response flow), `media/route.ts` + `media/[id]/route.ts` (library, alt-text edit)
- `authors/route.ts` (user list for byline assignment — editor+)

## 4. Dashboard UI (`app/(dashboard)/dashboard/cms/…` + `components/cms/…`)

- `posts/page.tsx` — status tabs (Draft / Pending Review / Scheduled / Published / Archived), search, author filter, status badges, row actions.
- `posts/new` & `posts/[id]/edit` — editor screen: `BlockTextEditor` (markdown) with `onFilesDrop` → `/api/cms/upload` → markdown image insertion with alt-text prompt; right rail panels: **Settings** (slug auto-gen/editable until published, excerpt, featured image + alt enforcement, primary + secondary categories, tags with autocomplete, guest byline), **SEO** (meta title 50–60 & description 150–160 char counters, canonical URL, noindex/nofollow toggles, live OG/Twitter desktop+mobile preview cards), **Publish** (status-aware: submit for review, approve/reject, schedule with future-date validation, publish, archive), **Revisions** (snapshot list, side-by-side line diff vs current, one-click rollback).
- `components/cms/`: `post-editor.tsx`, `seo-panel.tsx`, `social-preview.tsx`, `taxonomy-panel.tsx`, `publish-panel.tsx`, `revisions-panel.tsx`, `media-dialog.tsx`, `use-autosave.ts` (10s debounced background save + `localStorage` fallback with crash-recovery prompt), soft-lock banner (heartbeat every 30s; read-only + banner when another user holds a fresh lock).
- `categories/page.tsx` (hierarchical management) and `media/page.tsx` (library).
- Sidebar gets a "Content" group (Posts, Categories, Media) filtered to writer/editor/admin.

## 5. Public blog

- `app/blog/page.tsx` — server-rendered published index (includes due scheduled posts via publish sweep), category/tag browsing.
- `app/blog/[slug]/page.tsx` — `generateMetadata` (seoTitle→title, seoDescription→excerpt, OG/Twitter card incl. ogImage, canonical, robots from noindex/nofollow); markdown rendered with `react-markdown` + `remark-gfm` (no raw HTML → XSS-safe per PRD); old slugs resolve via `slugRedirect` → 301 `permanentRedirect`; archived posts 404 unless a redirect exists (config constant in `lib/cms/config.ts`).
- These sit outside the `/dashboard` proxy matcher — public, indexable.
