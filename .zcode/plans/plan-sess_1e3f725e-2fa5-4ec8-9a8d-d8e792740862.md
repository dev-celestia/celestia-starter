# Dedicated docs pages for the layout component family

## Goal

Every other component family has a dedicated page at `/docs/components/<slug>`; the 16 layout components (`packages/ui/src/components/layout/`) have none — they're only covered by summary tables in `components/index.mdx`, and the "open docs" button on each layout showcase card falls back to the generic components page (`showcase-card.tsx:84-86`). This plan creates one dedicated docs page per layout component, with live previews, sidebar navigation, and the showcase cards wired to their pages.

## Components covered (16)

`auth-shell`, `page-shell`, `dashboard-shell`, `sign-in-page`, `sign-up-page`, `forgot-password-page`, `reset-password-page`, `two-factor-page`, `dashboard-page`, `profile-page`, `settings-page`, `list-page`, `billing-page`, `status-page`, `not-found-page`, `error-page`.

Slug = file name (matches the existing showcase card ids, and `lib/docs.ts` derives routes from the filesystem, so `/docs/components/auth-shell` etc. work with no route changes).

## Changes

### 1. Live previews — `apps/web/components/docs/previews.tsx`

- Add imports from `@celestia-project/ui/layout/*` (deep-import convention used throughout the file).
- Add a `LayoutPreviewShell` wrapper: a fixed-height framed canvas (`h-[26rem] w-full overflow-hidden rounded-lg border border-border`) — layout components are full-page, so unlike `PreviewShell` they need a constrained viewport to render in; mirrors the frame the showcase uses for its layout demos.
- Add 16 exported preview functions (`AuthShellPreview`, `PageShellPreview`, …, `ErrorPagePreview`) rendering realistic demo content inside `LayoutPreviewShell`, with no-op callbacks (`onSubmit={() => {}}`). For `AuthShellPreview`, render both `variant="centered"` and `variant="split"` side by side. Adapt demo data from the showcase's existing demo constants in `apps/web/components/showcase/sections/layout-section.tsx` (`AUTH_SHELL_CODE`, `SIGN_IN_CODE`, `PAGE_SHELL_CODE`, `DASHBOARD_SHELL_CODE`, `LIST_CODE`, `BILLING_CODE`, `STATUS_CODE`, etc.) so docs and showcase stay visually consistent. `error-page` has no showcase constant — write its example from the component's props (it's `StatusPage` with 500 defaults plus a `detail` block).

### 2. MDX pages — `apps/web/content/docs/components/<slug>.mdx` × 16

Each page follows the exact `card.mdx` pattern:
- Frontmatter: `title` (display name) + `description` (one line).
- One-paragraph intro (what it does, when to use it — source material exists in `components/index.mdx`'s "Shells vs. pages" table).
- `<XPreview />` live preview.
- Copy-pasteable `tsx` usage block with the real deep import (`@celestia-project/ui/layout/<slug>`).
- Props/regions table (from each component's actual props, e.g. `AuthShell`'s `variant | maxWidth | logo | heading | subheading | aside | sidePanel | footer`).

### 3. Navigation — `apps/web/content/docs/components/meta.json`

Insert a new group between `"tooltip"` and `"other-components"`:
```
"---Layout & Pages---",
"auth-shell", "page-shell", "dashboard-shell",
"sign-in-page", "sign-up-page", "forgot-password-page",
"reset-password-page", "two-factor-page",
"dashboard-page", "profile-page", "settings-page",
"list-page", "billing-page",
"status-page", "not-found-page", "error-page"
```
`lib/docs.ts` renders `---X---` separators as sidebar groups and feeds pagination automatically — no other nav edits needed.

### 4. Wire the showcase cards — `apps/web/components/showcase/sections/layout-section.tsx`

Add `docsSlug="<card-id>"` to all 15 `ShowcaseCard`s (ids already equal the slugs). This is the pattern `buttons-section.tsx` and `feedback-section.tsx` already use; it turns every dead docs-link button into a working one.

### 5. Discoverability — `apps/web/content/docs/components/index.mdx`

Add one sentence + links in the "Layout & Structure" intro pointing to the new dedicated pages, so readers of the existing tables find them.

## Verification

1. `pnpm --filter web build` (or dev server) — confirms all 16 MDX pages compile and previews render.
2. Spot-check routes `/docs/components/auth-shell`, `/docs/components/list-page`, `/docs/components/error-page`, and the docs sidebar showing the new "Layout & Pages" group.
3. Screenshot the new pages (desktop + one mobile width) and run the visual-judge pass on them before delivering, checking the preview frames against the better-ui/better-layout rules (concentric radius on preview frames, spacing/grouping, no clipped controls, readable content at fixed height).

## Out of scope

Full-viewport showcase demo routes (`/design-system/layout/<slug>`) — a separate follow-up if wanted. No changes to `packages/ui` itself. `README.md` "Installed Features" unaffected (no feature added).
