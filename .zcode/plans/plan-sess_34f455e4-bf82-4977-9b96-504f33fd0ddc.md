# Celestia Dashboard — Standalone Full-Stack Prototype in `apps/celestia`

Build the production-grade prototype dashboard inside `apps/celestia` (pristine Next.js 16.3.4 + Tailwind v4 + App Router, standalone from the monorepo). Three modules: **User Management**, **Code Automation** (AI review/auto-fix, simulated workers), **OOB Testing Platform** (token + interactions, HTTP capture endpoint). Real DB, real auth, real APIs; heavy infra (GitHub App registration, Redis/BullMQ, Docker sandboxes, DNS :53 listeners) is simulated in-process.

**Per the app's AGENTS.md:** read the relevant Next 16 guides in `node_modules/next/dist/docs/` before writing each area — notably `proxy.ts` (new middleware convention, replaces `middleware.ts`), `route.md` (dynamic `params` are Promises), and async `cookies()`.

## 1. Setup & dependencies
- `pnpm install` in `apps/celestia` (it has its own lockfile/workspace).
- Add deps: `better-auth`, `drizzle-orm`, `pg`, `drizzle-kit`, `zod`, `@types/pg`, `shadcn`-style UI (init shadcn locally with Tailwind v4; add button, card, table, switch, badge, dialog, input, tabs, dropdown-menu, sonner, avatar, separator, scroll-area, sidebar components).
- `.env`: `DATABASE_URL`, `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`, `GITHUB_CLIENT_ID`, `GITHUB_CLIENT_SECRET`, `OOB_DOMAIN` (default `oob.local`).
- Drizzle config + `db:push` script inside the app.

## 2. Database schema (`lib/db/schema.ts`, Drizzle/Postgres)
- **better-auth core**: `user` (plus `role` text default `'member'`, `banned` boolean), `session`, `account`, `verification`.
- **Code automation**: `installation` (mock GitHub App install per user), `repository` (owner/name, `enableReview`, `enableAutoFix`, `trigger` enum, `tokenBudget`), `run` (type `review|autofix`, repo ref, status `queued|analyzing|patching|completed|failed`, tokensUsed, durationMs, githubUrl, error), `run_event` (seq, level, message, timestamp — powers the live log).
- **OOB**: `oob_token` (token, label, userId, createdAt, expiresAt), `interaction` (tokenId, protocol `DNS|HTTP|SMTP`, remoteAddress, `protocolData` jsonb, timestamp).

## 3. Auth
- better-auth server in `lib/auth.ts` (GitHub OAuth provider + admin-ish role checks), client in `lib/auth-client.ts` (`better-auth/react`), catch-all route `app/api/auth/[...all]/route.ts`.
- `proxy.ts` guarding `/dashboard/:path*` via `getSessionCookie()`.
- Sign-in page at `app/(auth)/sign-in/page.tsx` with GitHub SSO button.

## 4. API routes (`app/api/…`, all session-guarded)
- `users` — admin-only list / patch role / ban (User Management).
- `repositories` — list/create/toggle settings (repo matrix).
- `runs` — list + `runs/[id]` detail; `runs/[id]/stream` — **SSE** live log feed; `simulate` — POST to enqueue a mock PR-review or issue-fix job (simulates webhook ingestion; verifies HMAC header format).
- `oob/tokens` — CRUD; `oob/interactions?token=` — polling; `oob/stream?token=` — SSE; `capture/[token]` — public HTTP capture endpoint recording method/path/headers/body as an interaction; plus a demo generator for simulated DNS/SMTP interactions.
- **Worker simulation**: `lib/worker.ts` — in-process async jobs with staged progress (`queued → analyzing → patching → completed`), emitting `run_event` rows + an EventEmitter bus that SSE routes subscribe to. Token budget & max-3-attempt guardrails enforced. Pluggable `lib/llm.ts` stub where a real model key would go (canned findings output).

## 5. Dashboard UI (app router, `(dashboard)` route group, sidebar shell)
- `/dashboard` — overview: stats cards, recent runs, recent interactions.
- `/dashboard/users` — user table, role/ban actions (admin-only; server-checked).
- `/dashboard/repositories` — repo matrix with switches for Review / Auto-Fix, trigger select, token budget input.
- `/dashboard/runs` + `/dashboard/runs/[id]` — run history with status badges; detail view streams live logs via SSE (`[Queue]…[Analysis]…[GitHub]…` style lines), tokens, duration, outcome.
- `/dashboard/oob` — token generation, copyable payload URL, live SSE interactions feed, per-token history with protocol badges.
- Landing page `app/page.tsx` rewritten as a product landing linking to sign-in.
