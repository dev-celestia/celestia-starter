The blog index: category chips over a lead story and a card grid.

Category state is controlled from above rather than held here, because the filtered list is the consumer's — it may come from a router search param, a CMS query, or a static array. The component only draws the chips and reports which one was pressed.

```tsx
import { BlogIndexPage } from "@/components/layout-templates/blog-index-page"
import type { BlogPost } from "@/components/layout-templates/blog-index-page"

const posts: BlogPost[] = [
  {
    id: "tokens",
    title: "Scoring a colour ramp instead of eyeballing it",
    excerpt: "A status hue is a fill under white ink and ink on near-white.",
    category: "Design",
    author: "Ada Lin",
    date: "12 Sep",
    readingTime: "8 min",
  },
]

export function JournalPage() {
  const [category, setCategory] = useState("All")

  return (
    <BlogIndexPage
      eyebrow="Journal"
      heading="Notes from the design system"
      categories={["All", "Engineering", "Design"]}
      activeCategory={category}
      onCategoryChange={setCategory}
      featured={featuredPost}
      posts={posts.filter((p) => category === "All" || p.category === category)}
      onOpenPost={(id) => router.push(`/blog/${id}`)}
    />
  )
}
```

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `heading` | `string` | — (required) | Page headline |
| `posts` | `BlogPost[]` | — (required) | Card grid entries, already filtered by you |
| `description` | `string` | — | Supporting line under the headline |
| `eyebrow` | `React.ReactNode` | — | Pill above the headline |
| `categories` | `string[]` | — | Category chips; omit to hide the filter row |
| `activeCategory` / `onCategoryChange` | `string` / `(c) => void` | — | Controlled chip selection |
| `featured` | `BlogPost` | — | Lead story rendered wide, above the grid |
| `onOpenPost` | `(id: string) => void` | — | Fired when a card is activated |

`BlogPost` is `{ id, title, excerpt, category, author, date, readingTime? }`. Cards are `<button>`s rather than anchors, so the layout stays framework-agnostic — route the `onOpenPost` callback to your router.
