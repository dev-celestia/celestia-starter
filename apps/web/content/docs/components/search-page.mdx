The search results screen: a query bar, a facet rail, and a result list.

The query and the facet selection are both controlled. Search state is the canonical thing a URL carries — a result page that cannot be linked to, or restored on refresh, is not a result page — so keeping it here would put the only copy of it inside a component that unmounts on navigation.

```tsx
import { SearchPage } from "@/components/layout-templates/search-page"

export function ResultsPage() {
  const [query, setQuery] = useState("")
  const [facets, setFacets] = useState(initialFacets)

  return (
    <SearchPage
      title="Search"
      description="Across components, layouts and documentation."
      query={query}
      onQueryChange={setQuery}
      placeholder="Search the design system…"
      facets={facets}
      onToggleFacet={(facetId, optionId) => toggleFacet(facetId, optionId)}
      results={results}
      totalLabel={`${results.length} results in 0.04s`}
      onOpenResult={(id) => router.push(`/components/${id}`)}
    />
  )
}
```

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `query` / `onQueryChange` | `string` / `(value) => void` | — (required) | Controlled query |
| `results` | `SearchResult[]` | — (required) | `{ id, title, excerpt, meta?, badge? }` |
| `placeholder` | `string` | `"Search…"` | Query input placeholder |
| `facets` | `SearchFacet[]` | — | `{ id, label, options }`; the rail hides below `lg` |
| `onToggleFacet` | `(facetId, optionId) => void` | — | Fired by a facet checkbox |
| `totalLabel` | `React.ReactNode` | — | Caption above the results |
| `onOpenResult` | `(id: string) => void` | — | Fired when a result is activated |

Plus every [PageShell](/docs/components/page-shell) prop except `results`, which is omitted from the base type because `React.ComponentProps<"div">` already declares an HTML `results` attribute of a different type.

`checked` lives on each `SearchFacetOption`, so the facet state stays a plain array the consumer can rebuild from a URL.
