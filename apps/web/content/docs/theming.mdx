# Theming

All theme code in `apps/web` lives in one module: [`lib/theme/`](https://github.com/dev-celestia/celestia-starter/tree/main/apps/web/lib/theme). It owns the light/dark **mode** (via `next-themes`), the **accent palette** and **corner radius** overrides, their persistence, and the CSS-variable application — no other file may import `next-themes` directly or write theme CSS variables.

The underlying design tokens (the two base palettes, radii scale, elevation, motion) live in `@celestia-project/ui/globals.css` and are documented on the [Design System](/docs/design-system) page. This page covers the runtime layer on top of them.

---

## What it does

- **Mode** — `light`, `dark`, or `system`, resolved on `<html>` as the `.dark` class (`attribute="class"`, `defaultTheme="system"`). Toggling suppresses transitions so the switch snaps instead of smearing.
- **Accent palette** — eight accent presets (zinc, emerald, violet, blue, rose, orange, teal, yellow). Selecting one writes `--primary`, `--primary-foreground` and `--ring` as inline CSS variables on `<html>`, with distinct light/dark variants per preset.
- **Corner radius** — six `--radius` values from `0rem` to `1rem`.
- **Persistence** — accent + radius are stored in `localStorage` under `celestia-theme-palette` / `celestia-theme-radius` and re-applied on every load.
- **Boot sync** — the provider re-applies saved overrides on mount and whenever the resolved mode flips, on every page — independent of whether the customizer UI is mounted.
- **Keyboard shortcut** — <kbd>D</kbd> toggles light/dark anywhere (ignored while typing in inputs).

**Environment variables:** none — the theme system is fully client-side.

## File overview

```
apps/web/lib/theme/
├── index.ts               # Barrel — the only import surface (import from "@/lib/theme")
├── provider.tsx           # ThemeProvider: next-themes config, boot sync, "D" hotkey
├── palettes.ts            # PALETTES, RADII, storage keys, defaults (pure data)
├── settings.ts            # read/write localStorage + apply CSS variables (side effects)
└── use-theme-settings.ts  # useThemeSettings(): accent + radius state hook
```

Consumers elsewhere in the app:

| File | Role |
|---|---|
| `apps/web/app/layout.tsx` | Mounts `<ThemeProvider>` once, around the whole app |
| `apps/web/components/shared/theme-customizer.tsx` | The popover UI (palette grid, mode tabs, radius) |
| `apps/web/components/shared/navbar.tsx` | Renders `<ThemeCustomizer />` in the one navbar on every page |

## Setup

Already wired in the root layout — nothing to install:

```tsx
// apps/web/app/layout.tsx
import { ThemeProvider } from "@/lib/theme"

export default function RootLayout({ children }: { children: React.ReactNode }) {
  return (
    <html lang="en" suppressHydrationWarning className="antialiased">
      <body>
        <ThemeProvider>{children}</ThemeProvider>
      </body>
    </html>
  )
}
```

## Client usage

### Read / switch mode

Import `useTheme` from `@/lib/theme` — never from `next-themes` directly:

```tsx
"use client"

import { useTheme } from "@/lib/theme"

export function ModeToggle() {
  const { resolvedTheme, setTheme } = useTheme()
  return (
    <Button onClick={() => setTheme(resolvedTheme === "dark" ? "light" : "dark")}>
      Toggle mode
    </Button>
  )
}
```

### Read / change accent + radius

`useThemeSettings` returns the persisted settings, a `ready` flag (false until after hydration — gate anything that renders them), and setters that apply to the DOM and to `localStorage` immediately:

```tsx
"use client"

import { useThemeSettings, PALETTES } from "@/lib/theme"

export function AccentPicker() {
  const { settings, ready, setPalette } = useThemeSettings()

  if (!ready) return null

  return (
    <select
      value={settings.paletteId}
      onChange={(e) => setPalette(e.target.value)}
      aria-label="Accent palette"
    >
      {PALETTES.map((p) => (
        <option key={p.id} value={p.id}>{p.name}</option>
      ))}
    </select>
  )
}
```

### Full customizer

The complete popover (palette grid, light/dark/system tabs, radius picker, reset) is ready-made:

```tsx
import { ThemeCustomizer } from "@/components/shared/theme-customizer"

<ThemeCustomizer />
```

## Adding a palette or radius

Add an entry to `PALETTES` or `RADII` in `lib/theme/palettes.ts` — both light and dark variants for a palette, each with `primary`, `primaryForeground` and `ring` in OKLCH. Contrast rules from the design system apply: the accent must clear WCAG AA against its foreground in both themes. No other file needs to change; the customizer picks the entry up automatically.
