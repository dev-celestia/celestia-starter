The `@celestia-project/create` CLI creates a new project from the template, asks which features you need, and wires everything up so you can run `pnpm dev` immediately.

## Quick start

```bash
npx @celestia-project/create my-app
```

The installer will:

1. Ask which features you want (`auth`, `dashboard`, `blog`) — required features are resolved automatically
2. Clone the template and run `pnpm install`
3. Add/remove features through the feature manager (`features.json` stays in sync)
4. Write `apps/api/.env` and `apps/web/.env`, including a generated `BETTER_AUTH_SECRET`
5. Optionally push the database schema (`db:push`) and initialize git

## Non-interactive usage

```bash
npx @celestia-project/create my-app --features auth,dashboard
```

| Flag                 | Description                                                                    |
| -------------------- | ------------------------------------------------------------------------------ |
| `--features <a,b>`   | Comma-separated features to install. Dependencies (`requires`) are added automatically. |
| `--repo <url\|path>` | Template repository to clone. Also accepts a local git path for testing.        |
| `-h`, `--help`       | Show help.                                                                      |

## Requirements

- Node.js ≥ 20, `pnpm`, and `git` on your PATH
- A running PostgreSQL if you let the installer push the schema

## Database migration errors

If `db:push` fails during scaffolding (e.g. PostgreSQL isn't running yet), the CLI will show the exact commands to recover:

```bash
# Once your database is up:
cd my-app
pnpm --filter @workspace/db db:push

# Or with a one-liner:
DATABASE_URL="postgresql://..." pnpm --filter @workspace/db db:push
```

Need a local database? Start one with Docker:

```bash
docker run -d --name celestia-db \
  -e POSTGRES_USER=postgres \
  -e POSTGRES_PASSWORD=postgres \
  -e POSTGRES_DB=celestia \
  -p 5432:5432 postgres:16-alpine
```

## Testing the CLI locally

```bash
# Fastest — run directly with node (from the monorepo root)
node packages/cli/src/index.js my-test-app

# Simulate the installed bin via npm link
cd packages/cli && npm link
create-celestia my-test-app

# Most realistic — pack a real .tgz and run it via npx
cd packages/cli && npm pack
npx ./celestia-project-create-*.tgz my-test-app
```

Or use the npm scripts from `packages/cli`:

```bash
pnpm --filter @celestia-project/create test:run   # node direct
pnpm --filter @celestia-project/create test:pack  # tarball → npx
```

## Publishing

The CLI is published to npm under the `@celestia-project` org using the monorepo publish script:

```bash
# Dry run — previews what will be uploaded
pnpm publish:dry-run

# Publish all packages (@celestia-project/ui + @celestia-project/create)
pnpm publish:packages
```

`DEFAULT_REPO` in `packages/cli/src/index.js` points at the public template repository — update it if you fork.
To try the CLI from this repository without publishing, run `pnpm scaffold`.
