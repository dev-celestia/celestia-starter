Authentication runs entirely on the **backend** (`apps/api`). Better Auth handles email/password sign-up, Google OAuth, and two-factor authentication (2FA), and persists sessions through the Drizzle adapter. The frontend never touches the database or a server auth instance — it uses the Better Auth client over the `/api` proxy.

## Stack

| Layer | Technology |
|-------|-----------|
| Auth engine | [Better Auth](https://better-auth.com) (on the backend) |
| Database adapter | Drizzle ORM (PostgreSQL) via `@workspace/db` |
| Client | `better-auth/react` (frontend, over the proxy) |
| Plugins | Two-Factor Authentication |

## Environment Variables

Add the following to `apps/api/.env`:

```bash
BETTER_AUTH_URL=http://localhost:3000
BETTER_AUTH_SECRET=<generate with: openssl rand -base64 32>
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/celestia
GOOGLE_CLIENT_ID=your-google-client-id
GOOGLE_CLIENT_SECRET=your-google-client-secret
```

> `BETTER_AUTH_URL` is the **public** URL the browser uses to reach auth. Because the frontend proxies `/api/*` to the backend, the public URL is the frontend (`http://localhost:3000`).

## Server Configuration

The auth instance lives in `apps/api/src/auth.ts`:

```ts
import { betterAuth } from "better-auth"
import { drizzleAdapter } from "better-auth/adapters/drizzle"
import { twoFactor } from "better-auth/plugins"
// feature-manager:auth-imports:begin
// feature-manager:auth-imports:end

import { db } from "@workspace/db"

export const auth = betterAuth({
  database: drizzleAdapter(db, { provider: "pg" }),
  emailAndPassword: { enabled: true },
  socialProviders: {
    google: {
      clientId: process.env.GOOGLE_CLIENT_ID!,
      clientSecret: process.env.GOOGLE_CLIENT_SECRET!,
    },
  },
  plugins: [
    twoFactor({ issuer: "Celestia" }),
    // feature-manager:auth-plugins:begin
    // feature-manager:auth-plugins:end
  ],
  trustedOrigins: ["http://localhost:3000"],
})
```

> **Extension points:** the `auth-imports` / `auth-plugins` regions let installable features add Better Auth server plugins without overwriting this file. The client counterpart (`apps/web/lib/auth-client.ts`) exposes `client-imports` / `client-plugins`, and extra `user` columns can be contributed through the `user-fields` region of `packages/db/src/schema.ts`. See [Packages](/docs/packages) for the full marker catalog.

It is mounted as a catch-all in `apps/api/src/app.ts`:

```ts
app.on(["GET", "POST"], "/api/auth/*", (c) => auth.handler(c.req.raw))
```

## Client Usage

The frontend client (`apps/web/lib/auth-client.ts`) talks to auth through the same-origin proxy:

```ts
import { signIn, signOut, useSession } from "@/lib/auth-client"
```

### Sign in with email

```ts
const { error } = await signIn.email({
  email,
  password,
  callbackURL: "/dashboard",
})
```

### Sign in with Google

```ts
await signIn.social({
  provider: "google",
  callbackURL: "/dashboard",
})
```

### Access the current session

```tsx
"use client"
import { useSession } from "@/lib/auth-client"

export function Profile() {
  const { data, isPending } = useSession()

  if (isPending) return <p>Loading...</p>
  if (!data) return <p>Not signed in</p>

  return <p>Hello, {data.user.name}</p>
}
```

## Database Setup

The auth tables live in `packages/db`. Push the schema:

```bash
pnpm --filter @workspace/db db:push
```

> **Note on the feature manager:** the `auth` feature template under `features/auth` predates the frontend/backend separation and installs an integrated (in-`apps/web`) auth setup. The canonical, current authentication setup is the backend one described on this page and in [Backend API](/docs/backend).
